# Функциональное и исследовательское тестирование модуля расписания (Spaffy)

Комплексный аудит логики планирования занятий в веб-сервисе **Spaffy** (EdTech-платформа взаимодействия преподавателей и учеников).

📄 **[Открыть полный PDF-отчёт с доказательствами и скриншотами](./Spaffy_Functional_Testing_Report.pdf)**

---

## 🎯 Цели и область тестирования
* **Объект:** Модуль создания уроков, ролевая модель («Учитель» / «Ученик»), интерфейс календарной сетки в режиме «Неделя».
* **Цель:** Выявление дефектов бизнес-логики, рассинхронизации клиент-серверной валидации и интерфейсных ограничений, способных привести к срыву уроков.

## 🛠 Стек и техники тест-дизайна
* **Техники:** Анализ граничных значений (BVA), разбиение на классы эквивалентности (EP), исследовательское и попарное тестирование состояний.
* **Инструменты:** Chrome DevTools (Network, Elements, Console), Windows 10, Word/PDF Reporting.
* **Формат баг-репортов:** Заголовки по схеме «Что? Где? Когда?», предусловия, воспроизводимые шаги, фактический/ожидаемый результаты, оценка влияния на пользователя (User Impact).

---

## 🐞 Ключевые обнаруженные дефекты

| № | Тип | Описание дефекта | Серьёзность |
|---|---|---|---|
| **1** | Logic / Business | Автоматический перевод существующего урока в статус «Перенесено» при создании пересекающегося слота (без запроса подтверждения и выбора новой даты). | **Major** |
| **2** | Validation / API | Рассинхронизация клиентской и серверной валидации длительности (UI допускает 1–4 мин, бэкенд блокирует сохранение с неинформативной общей ошибкой). | **Medium** |
| **3** | UI / Boundary | Визуальное скрытие и недоступность карточки занятия при назначении на границу суток (23:55) в недельной сетке календаря. | **Medium** |
| **4** | UX / Usability | Сброс введенных данных формы без предупреждения при случайном клике по фону (backdrop). | **Minor** |

## ⚠️ Анализ рисков и дальнейшие проверки
1. **Timezone Offset:** Критически важно проверить поведение сетки при несовпадении часовых поясов учителя и ученика (риск смещения карточки на другой день или сдвига на час).
2. **UI Clashing:** Риск визуального схлопывания элементов при постановке занятий с минимальными интервалами.
3. **Групповые занятия:** Требуется отдельный прогон с масштабированием числа участников для проверки корректности статус-модели.
